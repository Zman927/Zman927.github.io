멀티테넌트 인사관리 시스템 백엔드

2026.09~진행 중 · 캡스톤디자인 4인 팀(백엔드 2인 중 1인)

여러 회사가 함께 쓰는 HR 플랫폼. 전체 API 184개 중 약 80개, 백엔드 테스트 482개 중 약 210개를 작성하고 PR 47건을 머지했습니다.

  • 모든 API가 공유하는 공통 기반 설계·구현: JWT 인증, 회사(테넌트) 간 데이터 격리, 역할별 권한·조회 범위 검사, 감사 로그, 급여 계좌번호 AES-256-GCM 암호화
  • 다단계 승인 엔진(승인선·승인함·재지정)과 휴가·평가·인사발령·재직상태 도메인 개발
  • 과거 이력이 중요한 인사발령·재직상태 데이터는 수정·삭제 없이 정정 레코드를 추가하는 append-only 방식으로 처리
  • N+1 개선: 승인함 목록에서 건마다 실행되던 신청자·결재 단계 조회(N건이면 2N회)를 PostgreSQL ANY·unnest 묶음 조회로 바꿔 페이지당 2회로 줄임
  • 시연 전 보안 점검: 역할 등록 권한, 업로드 파일(프로필 사진·로고·영수증) 재사용 문제를 찾아 수정
  • CI: PR마다 스키마·시드 검증 → 전체 테스트 → Docker 이미지 빌드를 거치게 하고, 필수 체크로 걸어 develop 브랜치를 보호

취약점 관리 API 서버

2026.08 · 개인 프로젝트

취약점 관리 REST API를 설계하고 컨테이너화·로컬 쿠버네티스 배포·CI 보안 게이트까지 한 흐름으로 구축했습니다.

  • bcrypt 해싱 + JWT 인증으로 쓰기 요청 보호, parameterized query로 SQL Injection 방지
  • Docker 이미지를 로컬 쿠버네티스(Deployment·Service·Secret)에 배포, JWT 비밀키는 K8s Secret으로 분리
  • node:test 기반 자동화 테스트, GHCR 이미지 자동 푸시(CD 1단계)
  • npm 번들 취약점: Trivy 게이트가 빌드를 막았지만 npm audit은 0건 → 이미지 내부 경로를 추적해 베이스 이미지에 번들된 npm 자체의 취약점임을 확인 → 런타임에 쓰지 않는 npm을 최종 이미지에서 제거해 0건으로 통과
  • 호스트-컨테이너 네트워크: 컨테이너 안의 localhost가 호스트 DB에 닿지 않는 문제를 DB 접속 정보 환경변수화로 해결해, 같은 이미지로 로컬·Docker·K8s 세 환경을 코드 수정 없이 지원
